# Статьи и исследования

Статический сайт на Zensical, публикация через GitHub Actions на GitHub Pages.

## Публикация в GitHub

В **Settings → Pages → Source** выберите **GitHub Actions**. Отправьте изменения в `main`: workflow соберёт и опубликует сайт. Ручной запуск: **Actions → Publish articles to GitHub Pages → Run workflow**.

Публичный адрес: https://rakki.github.io/fandoms/. Фактический адрес после публикации указан в **Settings → Pages**. При переносе репозитория или смене домена обновите `site_url` и ссылки `project.extra.alternate` в `zensical.toml`.

## Статьи на двух языках

Храните переводы в одинаковых относительных путях:

```text
docs/
├── index.md                     # Выбор языка
├── ru/
│   ├── index.md                 # Русская главная
│   ├── news/                    # Новости и обновляемые подборки
│   └── articles/                # Постоянные статьи
│       └── bestiary_monsters.md # Русская статья
├── en/
│   ├── index.md                 # English home
│   ├── news/                    # News and updated collections
│   └── articles/                # Permanent articles
│       └── bestiary_monsters.md # Добавьте английский перевод сюда
└── assets/                     # Общие изображения
```

Английского перевода бестиария пока нет: схема выше показывает, куда его добавить. Содержимое статьи и H1 должны быть на соответствующем языке; имя файла у пары переводов одинаковое. Например, заголовки `# Бестиарий монстров` и `# Monster bestiary` могут использовать общий файл `bestiary_monsters.md`.

Переключатель в шапке находит перевод по пути после `ru/` или `en/`. Если парного файла нет, открывается главная выбранного языка. Это определяется при сборке, без сетевых запросов и дополнительного JavaScript. Якорь раздела при смене языка не переносится, поскольку переведённые заголовки имеют другие идентификаторы.

Навигация автоматически включает все Markdown-файлы, H1 используется как название статьи. Языковые разделы находятся в одном дереве меню. Общий поиск ищет по всем статьям на обоих языках. Интерфейс темы остаётся русским: настройка `theme.language` действует на весь проект. Переключатель меняет язык материалов. Для полностью раздельных локализованных интерфейсов и поиска потребуются две сборки.

## Экспорт из Notion и изображения

### Два типа публикаций на главной

Вид публикации определяется папкой, дополнительных полей не требуется:

- `docs/ru/news/` и `docs/en/news/` — новости и обновляемые подборки;
- `docs/ru/articles/` и `docs/en/articles/` — постоянные статьи.

Переводы должны лежать в одинаковой папке и иметь одинаковое имя файла: например, `ru/news/weekly.md` и `en/news/weekly.md`.

Даты указывать не нужно: новости автоматически сортируются по времени последнего коммита, изменившего Markdown-файл. Добавили файл и сделали коммит — появилась новая публикация. Отредактировали статью и сделали коммит — она поднимается наверх. Обычный push без изменения статьи её положение не меняет. Изменение только изображения тоже не меняет дату Markdown-статьи.

История Git также сохраняет дату первого добавления. Сейчас для сортировки используется последнее изменение, с точностью до секунды; на главной показывается только день в UTC. У переводов даты независимы. Поля `date` и `updated` в Markdown больше не используются.

GitHub Actions загружает полную историю (`fetch-depth: 0`), затем `scripts/collect_news_dates.py` подготавливает даты для шаблона. Скрипт использует только стандартную библиотеку Python и Git, не меняет статьи и не требует новых зависимостей. Даты файловой системы после checkout не используются: они отражают время копирования репозитория, а не публикации. При переименовании история отслеживается через `git log --follow`, если Git распознает перенос файла.

Для постоянной статьи достаточно обычного Markdown в папке `articles/`:

```markdown
# Название статьи
```

Бестиарий пока находится в постоянных статьях. Чтобы сделать его обновляемой подборкой, перенесите Markdown-файл из `ru/articles/` в `ru/news/` и сохраните перенос коммитом. Общие изображения остаются в `docs/assets/bestiary_monsters/`; при таком переносе глубина статьи не меняется и ссылки на них остаются прежними. При переносе уже опубликованной статьи добавьте перенаправление со старого пути в `project.plugins.redirects.redirect_maps` файла `zensical.toml`.

На главной автоматически показываются три последние публикации из `news/`. Если их больше трёх, **«Показать больше»** раскрывает заголовки остальных в порядке от новых к старым. Ниже выводится полный список из `articles/` по названию. Каждая языковая главная использует папки своего языка; корневая главная показывает русские статьи и ссылки выбора языка. Вложенные папки тоже учитываются. Списки создаёт шаблон `overrides/home.html` при стандартной сборке Zensical, без дополнительных зависимостей или JavaScript.

Для статей достаточно H1 и основного текста, добавлять front matter не требуется.

### Копирование файлов

1. Экспортируйте выбранную страницу через **Export → Markdown & CSV**, включив файлы и изображения, и распакуйте архив в `notion-exports/` в корне проекта. Эта папка игнорируется Git и не публикуется. Экспорт вне `docs/` не создаёт дублирующих страниц на сайте.
2. Выберите язык (`docs/ru/` или `docs/en/`) и скопируйте Markdown в `news/` для обновляемой публикации или `articles/` для постоянной.
3. Убедитесь, что в начале есть `# Название статьи`. Уберите `title` из front matter, если название должно браться из H1.
4. Скопируйте изображения в общую папку `docs/assets/<имя-статьи>/` и замените в Markdown префикс папки Notion на относительный путь к ней. Для RU и EN используйте одни и те же файлы, повторно копировать изображения перевода не нужно.
5. Отправьте изменения в `main`. Редактировать конфигурацию или списки статей не нужно.

Изображения хранятся один раз в `docs/assets/`, в отдельной папке для каждой статьи. Из `docs/ru/articles/bestiary_monsters.md` и его английского перевода путь к общему изображению одинаков:

```markdown
![Описание](../../assets/bestiary_monsters/image.png)
```

Общая структура для двух языков:

```text
docs/
├── ru/articles/bestiary_monsters.md
├── en/articles/bestiary_monsters.md  # Будущий перевод
└── assets/bestiary_monsters/
    ├── image.png
    ├── image 1.png
    └── ...
```

Все 234 изображения бестиария уже находятся в `docs/assets/bestiary_monsters/`. Пробелы в ссылках кодируются как `%20`. Для статьи во вложенной папке добавьте ещё один `../` на каждый дополнительный уровень. При повторном экспорте сохраняйте имя Markdown-файла и общей папки картинок, заменяйте содержимое и обновляйте ссылки, если Notion изменил имена. Изображения копируйте локально, не подставляйте временные адреса файлов Notion.

У каждой пары переводов своя общая папка изображений, например `docs/assets/bestiary_monsters/`. При переносе экспорта замените исходный префикс папки Notion во всех ссылках на `../../assets/bestiary_monsters/`. Если Notion пронумеровал одинаковые картинки по-разному в двух экспортах, сопоставьте их по содержимому и направьте ссылки на существующие общие файлы. Обновление общей картинки действует сразу на обе версии статьи.

Для текущего сайта используйте Markdown-экспорт: Zensical сам создаёт оформление, оглавление и поиск. HTML-экспорт не нужен. Работа остаётся в Notion, а GitHub хранит выбранную публичную версию: экспорт → копирование Markdown и картинок → коммит → push. Загрузка напрямую по ссылке Notion сейчас не подключена.

Для H2–H4 автоматически создаётся оглавление. Ссылку на раздел можно скопировать у заголовка на опубликованном сайте. Ссылки Notion на другие страницы или разделы при необходимости заменяйте вручную на ссылки сайта.

Чтобы обновить статью, замените Markdown и изображения и отправьте изменения в `main`. Сохраняйте пути файлов, чтобы не менять адреса. Старый адрес `/articles/bestiary_monsters/` перенаправляется на `/ru/articles/bestiary_monsters/`.

## Локальный просмотр

С Python 3.13 из корня репозитория:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install zensical
python scripts/collect_news_dates.py
zensical serve
```

Откройте адрес из терминала; остановка — `Ctrl+C`. Для Windows активация окружения: `.venv\Scripts\activate`.

Для актуализации дат в локальном просмотре повторите `python scripts/collect_news_dates.py` после новых коммитов. У новых файлов без коммита скрипт временно использует время изменения файла только для локального просмотра; у отслеживаемых файлов — даты Git. Без подготовки дат сайт всё равно собирается, но новости будут без дат и без сортировки по времени. Сгенерированный `overrides/partials/generated-news-dates.html` игнорируется Git. Если репозиторий клонирован с ограниченной историей, сначала выполните `git fetch --unshallow`.

Документация: [языки](https://zensical.org/docs/setup/language/), [поиск](https://zensical.org/docs/setup/search/), [публикация](https://zensical.org/docs/publish-your-site/).
